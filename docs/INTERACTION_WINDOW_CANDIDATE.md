# 基于已有GT元数据的交互窗口候选

本工具为论文设计提供覆盖事实和候选窗口，不修改数据集、训练协议或可见性状态。事件定义只读取GT投影、可见实例框、逐相机原始world17与时间轴；不读取模型结果、RGB/mask/EXR像素，不扫描媒体哈希，不调用UE或GPU。事件采样不宣称首创，也不代表已经证明身份收益。

## 运行

在内层仓库的Python 3.9环境运行：

```powershell
.venv/Scripts/python.exe -m grf_ue_bridge.tools.analyze_interaction_windows --dataset G:/FutsalMOT_Dataset/v2_pose17_location_pilot_a01/dataset.json --output D:/projects/FutsalMOT_UEDataset/Saved/ResearchDiagnostics/interaction_windows_pilot_a02
.venv/Scripts/python.exe -m pytest tests/test_interaction_window_candidate.py -q
```

输出目录必须是全新的项目`Saved`子目录；拒绝覆盖、越界引用以及junction/symlink。输出`report.json`、`candidate_windows.jsonl`和`coverage.md`，报告绑定输入JSON/JSONL文本SHA。所有发布源文件只读，split保持原值。

## 候选定义

- 连续性：源帧必须连续；同时报告样本数/FPS的名义时长和首末时间戳跨度，不能把四视角计成四倍独立源时长。
- 尺度：可见实例框高度按长边640的LetterBox比例换算。这是框尺度，不是关节分辨率或检测难度标签。
- 框重叠proxy：交集面积/较小可见框面积至少0.2，连续至少2帧。完整前后分离context要求同一人物对前后各10帧不满足重叠条件。它不证明物理遮挡、身体接触、检测消失或身份恢复。
- 图像水平换序proxy：相邻帧投影髋中点的相对横坐标符号翻转，当前纵向距离不超过平均框高0.75倍，二维距离不超过平均框高1.5倍；髋位置不可用时才使用可见框中心并计数。抖动和姿态变化也可能造成翻转，不称物理轨迹交叉。
- 世界邻近proxy：地面髋中点距离不超过1.5米。只使用报告明确命名的一个参考相机，既不平均逐相机world，也不假定它们逐值相同。髋中点不是Actor根骨。
- 姿态重复proxy：只用肩到踝的12点，去髋中点平移、按地面髋横轴去航向、按肩中点到髋中点长度归一，RMS不超过0.01躯干单位视为近重复。另报告5/10/20/30帧间隔的回返。它不是动作类别或动画资产重复率。
- 根运动proxy：连续髋中点地面位移至少0.05米；10 FPS时相当于平均0.5米/秒。报告其与归一姿态近重复的交集，不能据此断言滑步或动画错误。

默认窗口60帧、步幅10帧，即10 FPS下6秒窗口、1秒步幅。按同队完整context事件数、同队换序数、全部完整context事件数、全部换序数、重叠pair-frame数依次排序；相同分数选更早窗口。同seed所有相机共用同一源窗口，不能分别挑出各相机“最好”的时间段。`candidate_only=true`；窗口可重叠，不能当作独立样本或随机拆分train/dev。

2026-10-23已实际执行一次元数据分析，输出为项目`Saved/ResearchDiagnostics/interaction_windows_pilot_a01`，耗时约2.87秒。针对测试4项通过。四seed为1042/1044/1048的train与1102的synthetic_dev；合计480个源时间样本、16相机序列、1920幅视图。每组120帧/10 FPS，名义连续12秒、首末时间戳跨度11.9秒；独立源名义总时长48秒。
